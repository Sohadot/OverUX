OAF-001

The OverUX Assurance Framework v0.1. A non-certifying research model for structured pre-release review without a composite UX score.

Version 0.1Issued 30 August 2026Research modelNo conformity claim
Purpose

Preserve dimensions. Preserve evidence.

A composite score can hide the thing that matters: which requirement failed, which evidence exists and which uncertainty remains. OAF keeps each dimension visible and records the release decision separately.

Claim boundaryOAF-001 is not a W3C, ISO, ACM or industry standard. It may reference external standards and research, but it does not confer compliance, certification or accessibility conformance.
Review dimensions

Six non-compensating lenses.

CodeDimensionReview questionExample evidence
C1ClarityCan the user understand current state, available action and likely consequence?Task walkthroughs, content review, state labels, user testing observations.
C2ContinuityDoes context and system state remain coherent across transitions, devices or interruptions?State-transition review, journey traces, persistence tests, navigation behavior.
F1FrictionIs interaction effort proportionate to the user's task and necessary constraints?Task-step analysis, redundant-entry checks, completion testing, workflow comparison.
A1AccessibilityAre applicable accessibility requirements and assistive-technology interactions addressed?WCAG testing, keyboard review, screen-reader checks, automated checks plus human verification.
T1TrustAre consequences, consent, reversibility and persuasion represented without avoidable deception or ambiguity?Consent-flow review, dark-pattern inspection, disclosure review, reversal path testing.
R1RecoveryCan errors be prevented, diagnosed and recovered from without disproportionate loss?Error-state inventory, validation behavior, undo/retry paths, support and recovery flows.
Decision states

Outcome is not a score.

A release state is attached to a defined review scope and evidence set. It does not transfer automatically to future builds, routes or contexts.

Not assessed

Unknown

Required evidence has not been collected or is stale.

Review

Escalate

Contextual judgment is required before a release decision.

Block

Hold

A blocking requirement or unresolved critical finding is present.

Release

Proceed

Applicable preflight conditions are evidenced for this scope.

Procedure

Minimum review record.

  1. Scope: identify build, route/flow, user context and release boundary.
  2. Requirements: list applicable internal constraints and external standards.
  3. Evidence: attach observations, tests and source references by dimension.
  4. Findings: record defects, uncertainty and non-applicable dimensions explicitly.
  5. Decision: assign Not assessed, Review, Block or Release with rationale.
  6. Freshness: invalidate or revisit evidence when material interface drift occurs.

What v0.1 deliberately does not define

No universal numeric thresholds, no cross-product ranking, no weighted average, no claim that six dimensions exhaust UX quality, and no automated release authority.
